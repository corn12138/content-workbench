# 架构与数据边界

Tauri 2 承载桌面窗口，React 管理界面，Rust 管理业务校验、SQLite、文件选择、剪贴板和系统浏览器入口。

| 模块 | 职责 |
| --- | --- |
| `src/renderer` | 稿件、阅读、发布记录与设置；编辑保存及退出协调；界面令牌见 `design-tokens.css` |
| `src/shared` | TypeScript 业务契约 |
| `src-tauri/src/store` | Rust 业务规则、版本与备份完整性检查 |
| `src-tauri/src` | 原生命令、受限文件操作、迁移与窗口生命周期 |
| `src/core` 与 `src/desktop` | Electron 回退内核和桌面层 |

前端通过明确的业务命令操作资料。原生窗口限制导航和新窗口；Markdown 与订阅 HTML 先净化再构造 React 节点（不注入 HTML），外链只允许普通 HTTP/HTTPS。数据库使用事务，恢复前验证格式与关联关系，并保留恢复副本。

Electron 与 Tauri 使用独立目录。Tauri 0.2 仍可导入旧 JSON，但默认导出完整 `.cwb`；Electron 保持旧版文字功能，拒绝 schema 2。升级前保留独立 v1 数据库。迁移对旧库做只读在线备份，在临时目录验证导出与恢复往返，再安装到尚不存在的目标。已有目标资料不会被覆盖。

关闭窗口先要求前端提交未保存的修改，原生端等待完成；无响应时提供恢复选择。调试冒烟钩子不进入 release 构建，数据和钥匙串探针必须显式启用 `probes` feature。

图片以内容哈希索引并存入 SQLite BLOB，与正文和订阅共用事务。完整备份是带版本、大小和 SHA-256 清单的 ZIP；恢复只读白名单条目到内存，不把归档路径解压到文件系统。历史版本引用的图片和已取消订阅的缓存内容继续保留。

RSS 通过 Rust 在资料锁之外获取，限制 DNS、重定向、超时及字节数，再以短事务去重入库；当前仅按需刷新。已取消订阅不会被旧响应重新启用，恢复操作递增代次并丢弃旧更新结果。前端在一个连续阅读区显示净化后的订阅正文结构（标题、列表、代码缩进、表格、链接），纯文字内容原样显示，并标明正文、摘要、文字缓存、无内容或已截取；支持缓存搜索和来源筛选。不执行源站脚本，外链图片点击后才加载。

X 发布使用独立原生模块：OAuth 回调 → 系统钥匙串 → API 发送 → 发布回执。平台操作串行，网络期间不持有资料锁。发布前把请求哈希写入独立持久化日志，未知结果不自动重试，成功后记录作品链接；资料恢复期间收到的回执不会误写到恢复后的稿件。X 真实账户尚未验收，其他平台自动发布、后台任务与同步尚未实现。本地写作仍可独立使用。

schema 3 支持 API 回执，schema 4 增加可选的结构化订阅正文，schema 5 增加 `publish_preparations`（未完成的发布准备，绑定稿件版本与内容哈希）、`draft_sources`（多篇笔记整理的来源）和 `feedback`（手动 / API 反馈快照）；每次升级前保存独立旧库，防止旧应用无法完整处理新增记录。schema 6 增加 `removed_drafts`：删除稿件先隐藏（同一次运行内可撤销），没有发布记录的在下次打开资料时连同历史版本清除，备份即时排除；有发布记录的保留隐藏行与全部历史，使记录仍指向发布时的版本，完整备份在 `workflow.json` 的 `removedDrafts` 中携带这些标记（为空时省略，保持 0.5.0 可读）。完整备份清单为版本 4，新增 `workflow.json`；旧备份缺少该文件时按空的发布准备与反馈恢复。内容备份不包含钥匙串凭证、防重日志，也不包含本机设置文件 `local-settings.json`（上次备份位置、公开 X Client ID）和阅读位置（WebView 本地存储）。恢复先只读预检，确认时重新读取文件并比对 SHA-256。
